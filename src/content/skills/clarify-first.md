# Clarify First（先澄清后作答）

**核心信念**：用户的请求往往不是「问题本身」，而是对问题的初步设想。直接回答会固化误解。先澄清，后作答——这不是拖延，而是为了让最终答案一击即中。

## 何时使用

- **模式一触发**：用户粘贴「先别急着回答…双向钢人论证…我的问题是：xxx」模板；或说「钢人论证」「steelman」「先问我一个问题」「别急着回答」「帮我厘清需求」「先别下结论」
- **模式二触发**：用户说「先问清楚再给方案」「迭代追问」「问到 95% 信心」「直到你完全理解」「多问我几个问题」「别急着出方案」
- **隐式触发**：用户提出的问题**模糊、重大、路径未明**（涉及取舍、目标不清、方案选择、后果重大），或我有理由怀疑自己误解了用户的真实意图。拿不准时默认模式二更安全（交付型任务理解偏差成本高）
- 不适用：纯事实查询、明确的小任务、用户已表达「直接做」的意图

## 模式选择

| 维度 | 模式一：钢人追问 | 模式二：迭代澄清 |
|------|----------------|----------------|
| 适用 | 问题重大、利弊未明，需要批判性审视想法本身 | 需求模糊、目标不明，需要充分理解后交付方案 |
| 核心动作 | 双向钢人论证 + 单问 | 单问循环直到 95% 信心 |
| 收敛标志 | 用户回答第一个问题 | 自评信心 ≥ 95% 或用户叫停 |
| 输出 | 明确判断 + 理由 + 下一步 | 最终方案（覆盖已确认需求要点） |

# 模式一：双向钢人追问（steelman probe）

对用户的问题执行以下四步，**严格停在第四步**，不抢先给结论：

### Step 1 — 重述问题（钢人化）

用最完整、最有力的方式，重述用户真正想解决的问题。不是复述原话，而是提炼到**最强版本**：把隐含的目标、约束、成功标准显式化。开头可用「我理解你真正想解决的是…」。

### Step 2 — 双向钢人论证

- **支持方**：给出支持用户当前想法（或问题所隐含的倾向）的**最强论证**——比用户自己说的更有力，2~3 条，具体、有依据，不稻草人。
- **反对方**：给出反对它的**最强论证**，2~3 条，同样具体有力。
- 每条论证一句话说清「论点 + 依据」，避免空泛。

### Step 3 — 找出分歧与关键变量

- 双方真正的**分歧点**在哪（一句话说清，通常是对某个事实或某个价值权重的不同假设）。
- **最可能改变结论的关键变量**是什么（1~2 个）——即：如果这个变量取值不同，结论就会翻转。

### Step 4 — 只问一个最关键的问题

- 基于 Step 3 的关键变量，**只问一个问题**——它能最大程度区分结论走向。
- 问题必须具体、可回答，附上选项或判断标准更好（例如「A 或 B？」「预算上限是多少？」「如果 X 不成立，你还会选它吗？」）。
- **一次只问一个**，禁止连珠炮。这本身就是信息：只问一个意味着我只关心最要紧的那件事。

### 用户回答后

1. 给出**明确判断**（不模棱两可，站一边，说明立场）
2. 给**理由**（引用 Step 2 的钢人论证 + 用户新提供的信息）
3. 给**下一步行动**（具体、可执行；若仍有关键未知，可再问下一个问题，继续单问循环，但每次都要有明确进展）

# 模式二：迭代澄清（iterate to clarity）

**目标**：在给出最终方案前，通过单问循环把对用户真实需求和目标的理解推进到 **95% 信心**。

### 流程

1. **开场理解声明**：用一两句话简述当前理解（简短，不展开论证），然后抛出**第一个问题**
2. **单问循环**：一次只问一个问题 → 根据回答更新理解 → 抛出下一个问题，直到收敛
   - 每个问题瞄准**当前最大的信息缺口**（目标、约束、优先级、成功标准、取舍偏好）
   - 每轮在内心（或简短标注）更新理解：已确认什么、未知什么、哪个缺口最关键
3. **收敛判定**：当自评信心 **≥ 95%**——即剩余未知只影响细节、不影响方案方向——立即停止追问，给出最终方案
4. **最终方案**：完整方案，开头一句话说明「基于你确认的 N 个关键点（目标/约束/偏好…）」；结尾标注残余假设（若仍有 <5% 的不确定）

### 信心追踪

- 每轮可向用户显示理解进度（例如「理解度：65% → 85%」），让用户感知收敛过程、减少「还要问多久」的焦虑
- 信心评估必须有依据：列出已确认信息 vs 剩余缺口，而不是凭感觉
- 典型收敛轮数：3~6 轮；**超过 8 轮仍未收敛**视为异常——停下来总结已确认信息，明确还缺什么，再问

### 纪律

- **一次只问一个问题**：硬规则，两模式共通
- **每问必有信息增量**：自检「这个答案会改变方案吗？」不会就不问
- **防过度追问**：剩余缺口只影响细节时直接给方案并标注假设，不要为凑 95% 而问
- **用户可随时叫停**：说「够了」「直接给方案」「别问了」→ 立即基于现有信息给方案，并说明剩余不确定性

# 行为纪律（共通）

- **一次只问一个问题**：这是本 skill 与普通追问的本质区别
- **不抢先给结论**：模式一硬停点在 Step 4；模式二硬停点在信心 ≥ 95% 或用户叫停
- **钢人而非稻草人**（模式一）：反对论证必须是最强版本，否则论证无意义
- **问题要有信息增量**：问之前先自检「这个答案会改变我的结论/方案吗？」不会就不问
- 若问题涉及实时事实（价格、政策、行情等），可借助联网搜索（byted-web-search）核实依据后再继续流程
- 用户明确表示「不用问，直接答」时，退出本 skill，正常作答

# 完成标准

- **模式一**：用户回答后，输出同时包含明确判断 + 理由 + 下一步行动，三者缺一即未完成
- **模式二**：信心 ≥ 95%（或用户叫停）后给出最终方案，方案覆盖已确认的需求要点并标注残余假设
